# 客户源码启动教程（Windows / MySQL 8.0.35）

适用：客户已安装 MySQL 8.0.35，在一台 Windows x64 电脑上运行系统。按顺序执行，每一步成功后再继续。

本文使用本次更新后的部署脚本。若下载的是旧代码，请先用随教程提供的文件替换同路径的 `deploy/mysql/Start-Backends.ps1`、`deploy/mysql/Start-MySql.ps1`；新版统一启动脚本具有 `MySqlBin` 参数。本文及脚本的本地修改尚未推送远端。

## 1. 需要编译吗

**后端需要编译，首次启动脚本会自动完成。建议安装 .NET 8 SDK；使用支持 net8.0 的新版 SDK 时，还需有 .NET 8 和 ASP.NET Core 8 运行时。** 前端安装依赖后运行 `npm.cmd run dev`，由 Vite 处理源码。

后端已编译且代码未变化时，可加 `-NoBuild` 跳过编译。前端按本教程运行时使用 `dev`；正式生成静态发布文件才执行 `npm.cmd run build`，并另行配置站点及反向代理。

## 2. 准备代码和环境

将完整源码解压到固定目录。本文以 `C:\IOTT` 为例，实际位置不同就替换命令中的目录。项目根目录应直接包含 `Host`、`MachineConnectionApi20260423`、`code20260423`、`deploy`。

安装以下环境，安装完成后重新打开 PowerShell：

| 软件 | 要求 | 官方入口 |
| --- | --- | --- |
| .NET | .NET 8 SDK，Windows x64 | [.NET 8 下载](https://dotnet.microsoft.com/en-us/download/dotnet/8.0) |
| Node.js | 建议 22.x，至少 22.12.0，包含 npm | [Node.js 下载](https://nodejs.org/en/download) |
| MySQL | 本教程使用客户已有的 8.0.35 服务端程序 | [MySQL 下载](https://dev.mysql.com/downloads/mysql/) |
| Docker Desktop | 本机保存历史采样数据时需要，按官方要求准备 WSL 2 等组件 | [Windows 安装说明](https://docs.docker.com/desktop/setup/install/windows-install/) |

在 PowerShell 中检查：

```powershell
dotnet --list-sdks
dotnet --list-runtimes
node --version
npm.cmd --version
& 'C:\Program Files\MySQL\MySQL Server 8.0\bin\mysqld.exe' --version
Test-Path 'C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe'
```

应看到可编译 net8.0 的 SDK、`Microsoft.NETCore.App 8.0.x` 和 `Microsoft.AspNetCore.App 8.0.x`、符合要求的 Node.js 版本、npm 版本、MySQL `8.0.35`，以及最后一个 `True`。MySQL 安装在其他位置时，修改上面和后面命令中的 `bin` 路径。

**已有 8.0.35 时按此教程指定安装目录，无需为了匹配旧脚本路径另装 8.4。** 脚本使用这些程序，在项目目录下创建独立数据库实例，端口为 `3307`，与客户原有 `3306` 实例使用不同的数据目录。

此方式针对全新客户项目数据目录。已由 MySQL 8.4 初始化的项目 `deploy/mysql/.runtime/data` 必须继续使用兼容的服务器版本；不要直接改用 8.0.35 启动该目录。

## 3. 启动数据库和两套后端

首次启动需要联网下载 NuGet 依赖。打开 PowerShell，执行：

```powershell
cd 'C:\IOTT'
powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy\mysql\Start-Backends.ps1 -MySqlBin 'C:\Program Files\MySQL\MySQL Server 8.0\bin'
```

脚本自动初始化数据库、生成连接配置、向空库导入随包数据、编译后端、恢复网关业务配置并后台启动服务。看到以下输出表示后端就绪：

```text
MySQL 8.0.35 ready at 127.0.0.1:3307; databases=IndustrialIoT,MachineCollection; local settings written.
Host ready at http://localhost:5173
Gateway ready at http://localhost:5087
```

已有后端运行时显示 `already listening`。可以打开 [Host 接口说明](http://localhost:5173/swagger/index.html) 和 [网关接口说明](http://localhost:5087/swagger/index.html) 检查服务。

脚本读取实际服务器版本，写入两套后端的 `appsettings.Local.json`。数据库账号和密码自动生成。两个数据库均无表时才导入随包 SQL；已有表时保留客户数据，网关已有非空 `App_Data` 时也会跳过恢复。

## 4. 启动前端并登录

后端就绪后执行：

```powershell
cd 'C:\IOTT\code20260423\code'
npm.cmd ci --include=dev
```

锁文件中的依赖下载地址使用 `registry.npmmirror.com`，需确认客户网络能访问该域名；只配置 npm 官方 registry 不等于替换了锁文件下载地址。`--include=dev` 确保 Vite 等启动工具被安装。等待依赖安装成功，再执行：

```powershell
npm.cmd run dev
```

保持该终端窗口打开，访问 **[http://localhost:4171](http://localhost:4171)**。如果终端实际显示其他端口，使用它显示的地址，并检查 `4171` 是否被另一套前端占用。

首次初始化管理员：用户名 **`admin`**，密码 **`admin@123`**。登录后进入“系统管理 → 权限管理”，编辑管理员，填写新密码并保存。

设备以离线状态分发，设备密码和 Token 已清空。按现场情况填写 IP、端口、协议及凭据，再测试设备连接。随包业务记录会恢复；随包数据不包含实时或历史采样值。

## 5. 保存历史采样数据（按需）

安装并启动 Docker Desktop，确认 Linux 容器引擎运行。在另一个 PowerShell 窗口执行：

```powershell
cd 'C:\IOTT'
docker.exe version
docker.exe compose version
powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy\influxdb\Start-InfluxDb.ps1
```

`docker.exe version` 应显示 Server 信息。首次执行会下载固定版本镜像并初始化 InfluxDB 3，等待 `InfluxDB ready` 输出。

进入设备页顶部“历史库设置”，开启“保存历史数据”，部署位置选择“本地”，核对地址 `http://127.0.0.1:8181`、数据库 `machine_collection`、组织 `default`、数据表 `datapoint`。

Token 显示“已配置”时留空保留；需要填写时，使用 `C:\IOTT\deploy\influxdb\.runtime\admin-token.json` 中的 `token` 值。点击“测试连接”，成功后点击“保存”。

设备与采集点配置完成后，点击“开始采集”，进入“历史采集记录”确认保存结果。Docker Desktop 在使用期间保持运行。离开或刷新设备页面会停止采集；关闭实时弹窗可继续采集。

## 6. 以后每次开机启动

后端已成功编译且代码未更新时，依次执行：

```powershell
cd 'C:\IOTT'
powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy\mysql\Start-Backends.ps1 -MySqlBin 'C:\Program Files\MySQL\MySQL Server 8.0\bin' -NoBuild
```

后端就绪后：

```powershell
cd 'C:\IOTT\code20260423\code'
npm.cmd run dev
```

需要历史库时启动 Docker Desktop 并按第 5 节确认 InfluxDB 就绪。前端依赖未变化时无需重复安装。

前端终端按 `Ctrl+C` 停止前端，后端和 MySQL 仍在后台运行。脚本未配置开机自启。更新代码需先停止对应旧后端进程，再去掉 `-NoBuild` 重新编译启动；已运行的后端不会被脚本自动重启。

## 7. 常见问题

| 现象 | 处理 |
| --- | --- |
| 不识别 `MySqlBin` 参数 | 使用本次更新的两个启动脚本；旧版统一脚本不接收该参数。 |
| 找不到 MySQL 程序 | 检查 `-MySqlBin` 指向实际安装的 `bin`，其中应同时有 `mysqld.exe` 和 `mysql.exe`。 |
| 找不到 dotnet、没有 SDK | 安装 .NET 8 SDK 并重新打开 PowerShell，用 `dotnet --list-sdks` 检查。 |
| npm 安装失败 | 核对 Node.js 版本，查看下载错误，确认可访问 npm；成功后再启动前端。 |
| 后端编译或启动失败 | 查看终端首个错误，以及 `deploy/mysql/.runtime` 内的 `host.stdout.log`、`host.stderr.log`、`gateway.stdout.log`、`gateway.stderr.log`、`mysql-error.log`。 |
| 提示端口被其他程序占用 | 先确认占用者；已运行的同一项目可继续使用，其他程序需调整端口或停止后再重试。 |
| 页面能打开但数据加载失败 | 先检查两个 Swagger 地址，再检查前端终端的代理错误。 |
| 出现 `initial-data.pending` 错误 | 说明上次导入中断；保留现场日志并核查数据库导入状态，再处理标记和恢复，避免直接删除数据库。 |
| 历史采集提示存储异常 | 检查 Docker 和 InfluxDB 状态、地址及 Token，重新测试连接并确认具有写入权限。 |

使用中保留 `deploy/mysql/.runtime` 以及网关运行目录的 `App_Data`；本教程默认位置为 `MachineConnectionApi20260423/MachineConnectionApi/MachineConnectionApi/bin/Debug/net8.0/App_Data`。更新源码时保留这些运行数据及本地配置，历史库另需保留 Docker 数据卷和 Token 文件。

## 8. 现场部署前还需核对的问题

以下为代码检查发现的具体边界，其中端口进程识别和关闭存储后的页面提示尚待代码修复。

| 情况 | 实际影响与处理 |
| --- | --- |
| 未部署 InfluxDB 就开始采集 | 网关默认启用 InfluxDB，写入失败返回 502。准备正式采集时先完成第 5 节。 |
| 不使用 MQTT | 网关默认启用本机 `127.0.0.1:1883` 的 MQTT。关闭历史库后仍会发布 MQTT，无 broker 时仍报错；按下文关闭不用的发布功能。 |
| 关闭所有存储，只看实时值 | 后端虽会正常返回 `skipped=true`，当前前端仍误报“存储异常”；仅 MQTT 成功且未写历史库时也会误报。此项需要页面逻辑修复。 |
| 使用 HNC SDK、精雕、GSKRM | 统一脚本只编译 Host/Gateway，没有编译对应的 32 位桥接程序；见下方额外准备步骤。 |
| 同一电脑存在两份源码 | 当前启动脚本只按程序集名识别已占用的后端端口，可能把另一目录的旧后端当作就绪。运行前核实进程完整路径，只保留本次部署的实例。 |
| 首次先在 IDE 单独启动后端 | 若已成功建表或生成非空 App_Data，再执行统一脚本会跳过初始快照，导致能登录但缺随包记录。首次应严格从第 3 节开始；发生后先备份并核查恢复范围。 |
| 使用旧传输记录续传 | 132 条本地文件引用中仅 4 个原文件随包提供，另外 128 个缺失。记录能显示不代表原文件存在，续传需重新提供相应文件。 |
| 换解压目录或清理 bin | 账户、任务等在网关 App_Data；程序文件还记录绝对路径。固定部署目录，升级先备份 MySQL 运行目录、App_Data、本地配置和历史库数据卷。 |
| 配置改了但未生效 | Local 配置优先于主配置，环境变量又优先于 Local。排查 `ConnectionStrings__Default`、`ConnectionStrings__MachineCollection`、`Database__ServerVersion`；项目脚本不是直接复用原 3306 库的配置方式。 |
| 从另一台电脑访问 | 浏览器使用“部署机 IP:4171”，并确认部署机防火墙允许该连接；后端可继续由部署机的 Vite 代理转发。实际网络连通需现场验证。 |

**不需要 MQTT 时**，在网关项目目录的 `appsettings.Local.json` 顶层合并以下配置，保留已有 `ConnectionStrings` 和 `Database`，然后重启网关；不要用这段内容覆盖整个文件：

```json
{ "Mqtt": { "Enabled": false } }
```

HNC SDK、精雕、GSKRM 客户还需安装 **x86 ASP.NET Core Runtime 8**（包含对应 .NET 运行时）；HNC 原生 DLL 另依赖 **x86 VC++ 2010 和 x86 VC++ 14.x** 运行库。仅安装 x64 SDK 不满足这些设备桥接程序的运行要求。

在项目根目录按所用协议选择构建（无需全部执行）：

```powershell
dotnet build .\Host\src\IndustrialIoT.HncSdkShim\IndustrialIoT.HncSdkShim.csproj
dotnet build .\Host\src\IndustrialIoT.JingDiaoShim\IndustrialIoT.JingDiaoShim.csproj
dotnet build .\Host\src\IndustrialIoT.GskShim\IndustrialIoT.GskShim.csproj
```

HNC/精雕驱动会按配置尝试发现并启动桥接程序。GSKRM 默认 IPC 模式还需在另一个终端运行以下程序并保持运行，其默认监听地址为 `http://127.0.0.1:39123`：

```powershell
& '.\Host\src\IndustrialIoT.GskShim\bin\Debug\net8.0\win-x86\IndustrialIoT.GskShim.exe'
```

同机多套 InfluxDB 部署也需要单独规划：现有 compose 固定容器及数据卷名，不会随源码目录自动隔离。页面修改的历史库配置位于 App_Data，重跑部署脚本后仍应以页面“测试连接”结果为准。

## 9. 验收与验证范围

完成后确认：两个后端就绪、前端可登录、业务记录能显示；配置现场设备后另测设备连通和采集；启用历史库后另测新采样数据保存。

本次已核对脚本、依赖说明、初始化 SQL 和页面入口，Host、Gateway 与前端已在独立输出目录构建通过，14 个随包文件的校验和与大小均通过。后端构建使用本机 .NET SDK 9.0.307；前端使用已有依赖构建，未模拟客户全新联网安装。端口误认已用隔离测试复现。MySQL 8.0.35 的完整数据库初始化、现场设备连接和 Docker 历史库部署仍需在相应环境验收。客户已有的原数据库实例与本教程创建的项目独立实例是不同实例。
