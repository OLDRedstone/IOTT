# 评价流程口径与验收清单

本文说明客户原型落地时的计算口径和验收方法，不代表已经完成真实机床验收。自动回归只能使用隔离的假设备、HTTP 模拟和临时文件。

## 1. 三种分数、两种状态

- **分项评分**：按本次执行保存的结构化评分规则，把有依据的测量值映射为 0–100 分。0 分是有效结果；未测量、缺附件、不支持或证据不足时为空，不补默认分。
- **任务总分**：本次所选测试项目分数的简单平均；任何所选项目未评分时，任务总分保持待评分。它不是知识库综合评价分。
- **知识库分类分与综合分**：按记录快照中的项目、二级分类、一级分类权重逐层计算。分类加权贡献为分类分乘以该分类权重。正权重项目未评分时，不得用 0 或已评分项目的平均值冒充完整综合分；零权重未评分项不影响总分。
- **执行状态**：描述任务是否等待、执行中、执行完成或执行异常。
- **达标结论**：由独立的达标线判断。正常执行完毕但未达标，不等于程序执行失败。未配置达标线时，不能自动宣称通过。

客户任务原型中的随机示例值不是验收依据，例如协议覆盖率 246% 不得进入真实算法。达标线和满分档位可能不同，不能相互替代。旧 `/api/metrics` 中的隐藏 `Threshold` 不应决定新版评价任务的判定。

## 2. 七项指标的默认评分口径

以下档位来自评价指标管理原型，是可配置的评分规则，不是客户已确认的生产验收线。

| 项目 | 测量口径 | 默认评分 |
| --- | --- | --- |
| 工控协议覆盖率 | 已验证协议与选定标准协议集合的交集比例；别名归一，不重复计数 | 覆盖率百分比对应 0–100 分 |
| 通讯稳定性 | 实际协议读操作连续成功的时长；记录中断、采样间隔和观察时长 | ≥30 分钟：100；≥20：80；≥10：60；否则 0 |
| 最大并发连接数 | 明确是不同设备并发还是同一设备连接数；逐档增加并记录连续失败终止条件 | ≥4：100；≥3：80；≥2：60；否则 0 |
| 传输协议覆盖率 | 有成功传输依据的协议数量；配置存在与实际传输成功分开记录 | ≥2 种：100；1 种：60；0 种：0 |
| 文件完整性 | 当轮测试 0.1、1、10、20 MB 样本并回读比较；缺样本不能当完整测试 | 100%：100；≥75%：80；≥50%：60；否则 0 |
| 传输速度 | 本轮约 10 MB 标准文件成功传输的字节数及耗时 | ≥10 MB/s：100；≥5：80；≥2：60；否则 0 |
| 文件大小 | 本轮按 1、10、200 MB 逐档测试，记录最大成功文件 | ≥200 MB：100；≥10：80；≥1：60；否则 0 |

界面使用的 MB/KB 按二进制换算时，应明确为 1 MB = 1,024 KB、1 MB = 1,048,576 字节。不能把 200 KB/s 的达标线直接与数值单位为 MB/s 的实测值比较。

配置中的协议名称并不能证明设备真实支持该协议。只有 TCP 端口建连成功也不能代替持续应用层通讯。原型附件的文件名、大小元数据不是已经上传的测试文件；历史传输统计不能冒充本轮传输实测。

## 3. 操作顺序

1. 核对设备来源：网关机床列表与 IoT Host 的设备存储不是同一份数据。确认执行服务可以找到所选设备，不以某一层列表中的存在推断另一层已经同步。
2. 在评价指标管理中选择机床类或加工中心类，维护标准协议集合、评分档位、独立达标线、测试参数和真实附件。真实通讯测试还需配置可安全读取的地址、数据类型；文件测试需指定允许写入的测试目录，不能靠猜测点位或生产路径完成验收。
3. 检查同级权重。允许保存明显未平衡的配置草稿，但不能把未平衡草稿当成已完成的综合评价。
4. 创建任务，选择类别、设备和本次项目。若测试不同设备并发，明确选择被测目标，不把单机任务静默扩大成全设备测试。
5. 文件写入测试必须获得设备负责人许可并明确启用；未授权不得上传。上传测试文件不能执行数控程序，不能覆盖设备上的现有文件。
6. 执行时查看服务端真实进度、当前项目、原始值、测量来源、证据、单项得分和达标结论。
7. 将完成的任务导入知识库；核对执行时设备和指标快照，补充基础信息及其他项目的人工评分。
8. 检查分类得分、分类加权贡献和综合分，再保存、导出 Excel/PDF。
9. 编辑旧评价时重新同步任务，应另存为新评价并保留原记录。只按稳定项目 ID 迁移可匹配的人工数据；来源、规则快照及执行编号必须取自新任务。

“最多 7 个不同目标任务并行”是任务调度能力，不是“最大并发连接数”指标已经通过的证据。

## 4. 隔离自动回归

### 指标阈值操作

在“评价指标管理”选择类别，点击具体评价项目的“编辑”，在窗口顶部的“达标阈值”填写比较方式、数值和单位，再保存。

- 自动项目的阈值用于下一轮任务的达标判定，与评分档位分开；支持兼容单位换算。
- 人工项目也可保存阈值和自定义单位，但仍由人工核验，不因此自动执行或给分。
- 数值 `0` 是有效阈值；“清除阈值”表示不设置。历史任务和知识库记录保留执行/保存时的快照。
- 工控协议填写覆盖率百分比；传输协议填写实测协议种数，两者不是同一口径。

### 回归入口

在仓库根目录执行。下列命令是验收入口；具体通过情况以本次实际运行输出为准。

```bash
node --test code20260423/code/tests/evaluation-*.test.mjs code20260423/code/tests/verify-task-*.test.mjs
npm --prefix code20260423/code run build

dotnet run --project MachineConnectionApi20260423/MachineConnectionApi/MachineConnectionApi.Tests -- --evaluation-indicators
dotnet run --project MachineConnectionApi20260423/MachineConnectionApi/MachineConnectionApi.Tests -- --evaluation-pipeline
dotnet run --project MachineConnectionApi20260423/MachineConnectionApi/MachineConnectionApi.Tests -- --evaluation-knowledge
dotnet run --project MachineConnectionApi20260423/MachineConnectionApi/MachineConnectionApi.Tests -- --verify-task-runner
dotnet run --project MachineConnectionApi20260423/MachineConnectionApi/MachineConnectionApi.Tests -- --evaluation-pdf
dotnet run --project Host/tests/IndustrialIoT.Verification.Tests
dotnet run --project Host/tests/IndustrialIoT.Protocols.Tests -- --verification-transfer
```

`--evaluation-indicators` 包含人工阈值持久化和历史快照回归；`--evaluation-pipeline` 包含 HTTP 文件传输适配；`--verify-task-runner` 包含共享执行限制与任务恢复。另可单独使用 `--verify-runtime`、`--verify-http-transfer` 定位。

设置 `EVALUATION_PDF_OUTPUT` 后运行 `--evaluation-pdf` 可生成任务、知识库和长文本分页样本；测试数据不代表实际设备结果。PDF 使用嵌入字体的实际字宽换行，跨页重复表头和短项目标识。

不要直接运行测试程序的默认全量入口来替代隔离回归：其他入口可能要求真实数据库或设备环境。

重点检查：

- [ ] 两类别配置隔离，自动绑定各 7 项，普通新增指标不被冒充自动测试。
- [ ] 达标规则、评分规则、协议集合、附件和参数改变后，下一次执行使用新配置；旧任务快照不变。
- [ ] 新任务不受旧隐藏阈值影响；单位换算、档位边界、零分和未评分正确。
- [ ] 持续通讯不以短时 TCP 握手替代；并发测试对象与上限明示。
- [ ] 文件测试需要真实附件和写入许可，不覆盖已有远端文件、不执行程序、不借历史记录补结果。
- [ ] 200 MB 样本可走完整上传链路，超限、伪造大小、非法扩展名和路径被拒绝。
- [ ] 整体与分项进度来自真实执行，长任务不会因前端普通请求超时而显示虚假完成。
- [ ] 未达标与执行异常分开；已有 7 任务并行、同目标互斥及防陈旧刷新回归仍通过。
- [ ] 真实单项评分同步到知识库，历史无分数仍为空；不丢失合法零分及自定义小数分。
- [ ] 新增、同步和模板下载支持两类别；重复 run、版本冲突和历史快照保护仍有效。
- [ ] 真正的二进制 `.xls` 与 `.xlsx` 均可导入，损坏文件、超限数据和 XML 外部实体被拒绝。
- [ ] 分类分、小计、加权贡献和总分在界面及报表口径一致；PDF 中文、长文本和跨页不截断。

## 5. 真机验收边界

隔离回归通过不等于设备已通过验收。正式执行前，还需确认：被测机器与数据来源、协议实际读/写能力、允许的并发负载、测试目录及清理方式、文件传输上限、持续测试窗口，以及客户确认的达标线。

若部署在 IIS、Nginx 或其他反向代理后，还需单独确认代理的请求体限制能容纳 200 MiB 附件及 multipart 开销，并允许合理的大文件传输时间；应用层提高限额不代表外部代理已同步放行。设备端文件接口的限额与超时也应独立核验。

本轮开发不得为了验证功能而对真实机床发起负载测试或文件上传。缺少真机证据时应记录待验收项，而不是补分或宣称通过。
